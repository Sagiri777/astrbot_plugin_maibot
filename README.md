# Mai for AstrBot

Mai for AstrBot 不是一份单纯的“拟人化提示词”，而是把
[MaiBot](https://github.com/MaiM-with-u/MaiBot) 的核心交互思想适配到 AstrBot：
先观察聊天、判断是否应该行动，再生成自然回复，并从真实交流中逐渐积累表达方式、
圈内语言、互动成败和对当前用户的有限了解。

本插件面向 AstrBot API 独立实现，没有复制上游框架的源码、数据库或内置角色。

本次对照上游 **2026-10-21** 的
[`5c7637e`](https://github.com/MaiM-with-u/MaiBot/commit/5c7637e6913c84d1c3d5e742fa9e95a7e70d3501)，
重点参考 `maisaka_expression_selector.py` 的每轮表达筛选、`jargon_context_matcher.py`
的真人消息匹配，以及 Replyer 对真实发言与内部规划的区分。

同时参考 [Neo-MoFox](https://github.com/MoFox-Studio/Neo-MoFox) 截至 **2026-10-21**
默认分支的 [`c4cc1b2`](https://github.com/MoFox-Studio/Neo-MoFox/commit/c4cc1b25943a85c283fb96b670710b0f7262bf5e)
（提交时间 2026-10-17），将其新版聊天器的情境更新、群聊支线和互动连续性设计适配到现有插件。

**2026-10-24** 又阅读了 [Nekro Agent](https://github.com/KroMiose/nekro-agent)、
[Starlit](https://github.com/Unclecheng-li/starlit) 和 [tingfeng](https://github.com/DTXingFeng/tingfeng)
的实际对话代码，分别借鉴低信息量消息中的焦点定位、明确收尾后的克制，以及跨多条回复的
自我重复抑制。只适配通用机制，不复制角色素材、虚构生活、随机情绪或强制碎片化表达。

## 当前能力

### Planner → Replyer

群聊中未被直接唤醒时，Planner 可以阅读同一聊天最近的消息，只输出结构化的
`reply` 或 `ignore` 决策。决定回复后，回复意图与建议语气会作为临时上下文交给
AstrBot 原有回复模型；最终可见文本仍由当前人格、工具和会话生成。

这让自主回复从“随机概率触发”变为“根据聊天时机判断”，同时保留冷却、判断间隔、
置信度阈值和群聊白名单。默认连续自主发言 2 次后会至少静默一次，精准提及不受此限制，
避免形成逢话必接的机械节奏；`max_autonomous_reply_streak=0` 可关闭该限制。
同一聊天只允许一个正在进行的决策；决策期间如果有了更新
的人类消息，丢弃旧决策，避免对已经解决或转移的话题继续插话。Planner 的上下文包含
机器人实际发送成功的回复，并标记 `role=assistant`，避免重复回答。机器人回复不会进入
社会学习批次。

Planner 将旧背景与本轮最新消息分开输入，并参考当前聊天最近 4 次判断。
历史决策中的 `reply` 只代表计划；只有发送后钩子取得最终可见文本时才标记 `delivered`。
先前忽略不阻止回应新请求，先前计划参与也不要求在话题结束后继续接话。
决策记录只放在内存中，按聊天隔离，`/maiforget scope` 会一并清除。

`conversation_focus_enabled` 默认开启。最新一条只是“哈哈”“确实”等低信息量接话时，
Planner 可以从最近四条真人消息中选择信息更充分的一条作为建议焦点，而不是机械回复最后
一个语气词。它不会因此必然发言：如果接话本身已转移话题或无需回应，仍应选择沉默。
最新的精准提及、引用、提问、正式任务与普通有内容消息始终优先，旧焦点不能覆盖新请求。
该功能只做本地确定性评分，不增加模型调用。

### 互动衔接与话题定位（Neo-MoFox）

`interaction_context_enabled` 默认开启，不增加模型调用。它把上游的几项设计落到实际请求中：

| 上游设计 | 本插件的适配 |
| --- | --- |
| 旧背景与最新事件分开理解 | Planner 分栏输入，Replyer 临时参考明确以最新用户表达为准 |
| 群聊允许多条话题并行 | 读取 AstrBot 的真实引用 ID，先在缓冲区找关联支线，再应用上下文条数限制 |
| 精准辨认回应对象 | 读取 `At` 与 `Reply` 的平台 ID，同名昵称不会被当作精准提及机器人 |
| 避免反复追问与空洞附和 | 临时提供最多 3 条近期机器人发言，每条最多 400 字，帮助模型接续已说过的话 |
| 情境、语气随新表达变化 | 稳定规则要求放下已结束或被纠正的旧情境，情绪跟随交流变化，人格无需逐句表演 |
| 计划、工具结果与实际发言有区别 | 决策记录带发送状态，工具调用与内部思考不作为近期可见发言注入 |

例如群里先聊发布，随后多人聊游戏，此时有人引用发布消息说“已经修好了，明天上线”，
插件会用发布支线进行历史注入、表达筛选参考和黑话/回想召回，减少无关游戏话题干扰。
引用超出缓冲区时，使用平台提供的引用正文，不拿相邻闲聊补齐。缺少引用元数据时按普通
上下文处理，不猜测消息之间的关系。不会改写 AstrBot 已有的会话历史或其他插件提供的上下文。

私聊即使没有开启观察，也可临时读取本次请求原有的助手历史以避免重复追问；这不会开启
私聊学习或保存聊天正文。平台类型只用于理解消息可见范围，不推断现实地点、距离或关系，
角色扮演也不作为现实人物事实学习。关闭该开关可停用互动规则、临时定位及引用支线筛选；
Planner 的新旧消息分栏和决策记录仍随 Planner 工作。

这是上下文组织和生成指引，没有额外情绪模型。引用关联受平台
元数据及缓冲区范围限制；发送状态依据 AstrBot 的发送后钩子，不代表平台送达回执。未触发该
钩子的流式发送无法进入插件观察记录，后续请求可使用 AstrBot 保存的会话历史。

具体参考：新版 [`utils/prompts.py`](https://github.com/MoFox-Studio/Neo-MoFox/blob/c4cc1b25943a85c283fb96b670710b0f7262bf5e/plugins/neo_default_chatter/utils/prompts.py)
的互动、情境与社交规则，旧版 [`utils/decision_agent.py`](https://github.com/MoFox-Studio/Neo-MoFox/blob/c4cc1b25943a85c283fb96b670710b0f7262bf5e/plugins/default_chatter/utils/decision_agent.py)
的历史判断参考，以及 [`components/actions/send_text.py`](https://github.com/MoFox-Studio/Neo-MoFox/blob/c4cc1b25943a85c283fb96b670710b0f7262bf5e/plugins/neo_default_chatter/components/actions/send_text.py)
对可见发言与内部规划的区分。保留 AstrBot 原有的工具和发送链路，不引入上游的 Action 运行时、
暂停标记、内部独白或人工打字延时。

### 行为结果学习

开启后，每次 Planner 触发的自主发言都会在实际发送成功后建立反馈窗口。插件观察随后
几条真实用户消息，再让评估模型判断本次互动是成功、部分有效、失败还是证据不足。

有效结果会被泛化为“情境—做法—结果—经验”，按聊天隔离保存。评估必须引用发言后
真实存在的消息来源编号，不能只凭机器人自己的回复给自己打分。相似场景下，Planner
会召回最多 3 条历史经验；连续失败且低分的经验会被自动停用。

这部分只保存泛化后的行为经验，不持久化完整反馈聊天和机器人原回复。

### 跨聊天 Focus

Focus 为自主发言 Planner 提供一个全局关注槽：

- 普通消息只能延续当前关注的群聊，不能立即被其他群抢走；
- 当前群在配置时间内没有新消息后，其他群可以取得关注；
- 明确唤醒机器人可以强制切换关注群；
- Focus 白名单可以限制参与竞争的聊天范围。

Focus 被切换或手动释放后，原聊天尚未发出的规划结果会被丢弃。

Focus 不会阻止 AstrBot 对直接 @、命令或正常私聊的响应，只控制插件的自主发言。

### 中期聊天回想

中期回想复用社会学习批次，将有后续价值的共同经历、公开约定、项目进展或持续话题
压缩为：

- 简短标题和可独立理解的摘要；
- 1 到 6 个召回线索；
- 重要度和所属聊天范围。

记录必须引用本批次真实消息来源。插件只持久化压缩结果，不保存原始聊天正文；寒暄、
临时情绪和没有形成结果的碎片会被要求跳过。

Planner 和 Replyer 只在当前或近期消息命中召回线索时使用相关回想。出现“上次”
“之前”“还记得”等明确回忆表达但没有精确命中时，可以召回最近的重要记录。回想
不会跨聊天流共享，也不会把私聊内容带入群聊。

### 社会化学习

插件可以按聊天隔离收集真实用户消息，达到批次大小后在后台提取：

- 情境化表达习惯：什么情况下可以怎么说，以及适用触发词。
- 圈内黑话：特殊缩写、梗或群内短语及其语境含义。
- 可选人物事实：当前说话者明确自述的稳定、低敏感度偏好。

所有学习结果必须引用本批次存在的消息来源编号。人物事实学习、私聊观察和群聊人物
事实注入默认关闭。

### 语境召回

正常 LLM 回复前，插件会按当前消息选择：

- 与本轮消息或 Planner 回复意图匹配的已学表达习惯，无匹配时不注入；
- 当前或近期聊天中实际出现的已学黑话；
- 与当前说话者对应的低敏感度事实；
- AstrBot 群聊上下文未启用时插件观察到的近期群聊记录；
- Planner 为本轮回复准备的内容与语气指引。

这些动态内容使用 AstrBot 临时内容块，不写入会话历史。稳定人格和表达规则保留在
系统提示词中，方便模型服务端缓存。`context_injection_messages=0` 会完全关闭近期消息
缓冲区注入与基于这些消息的召回；当前平台明确引用和请求自带的历史仍可用于互动定位。
当前消息不会再次作为历史消息注入。黑话只匹配真人发言，
英文缩写按词边界匹配，避免把 `ai` 当作 `rain` 中的黑话。

### 每轮表达语义筛选

开启 `expression_selection_enabled` 后，从最多 12 条候选中，结合最新消息、近期对话和
Planner 指引选择 **0 到 3 条**表达习惯。可以在没有字面触发词时选中语义相关表达；
严肃求助、明确格式要求与闲聊玩笑应区别处理，没有适合表达就返回空结果。

筛选使用 `expression_selector_provider_id`，留空使用当前聊天模型。仅在存在候选表达时
增加一次调用，15 秒超时；模型报错、格式无效或返回空数组时，使用原有人格风格。
默认关闭此额外调用，使用本地关键词匹配。候选池使用关键词与频次排序，尚未引入上游
的向量检索，因此候选很多时仍可能漏掉低频但相关的表达。

### 实际输出对比

管理员可以执行 `/maieval 测试消息`。插件使用当前聊天的实际模型、最近一次请求中的
原始系统提示词，以及相同的近期聊天文本，分别生成未增强与增强回复，再随机打乱两者
的 A/B 顺序进行评审。显示两份完整回复，以及任务完成、事实依据、自然表达三个维度
的 1～5 分评分。评审失败也会保留两份原文，供人工比较。

对比调用直接走 AstrBot 的请求序列化与 `llm_generate`，临时表达参考会真正进入模型
输入；测试请求、回复与评分不写入会话或学习存储。命令的对比结果会显示在执行它的聊天中。
必须先在当前聊天正常对话一次，取得实际人格提示词。每次命令通常产生 3 次模型调用，
开启语义筛选且有候选时另加 1 次。`evaluation_judge_provider_id` 可指定独立评审模型，
留空时使用当前聊天模型。

这是文本层面的对比，不执行工具，也不覆盖图片、语音、完整会话历史和其他插件的
请求处理。两次生成都限制最多 1200 个输出 token，较长任务可能被截断，需要人工检查。
模型评分可能有偏差，单次胜出不能证明稳定提升。验收时请用多条真实消息重复测试，
优先确保任务完成和事实依据不退步，再看表达是否更自然。

### 自然表达层

- 保留 AstrBot 当前人格，不覆盖身份和工具能力。
- 区分群聊与私聊的互动习惯。
- 减少客服套话、机械总结和无必要 Markdown。
- 根据问题复杂度自然改变回复长度。
- 允许少量偏好、幽默和情绪，但不通过编造经历来假装真人。
- 支持管理员手工维护“情境 → 表达方式”规则和备用风格。
- 明确保留代码、JSON、详细分析等任务的格式与完整性要求。
- 默认关闭随机备用风格，避免在严肃话题中抽到幽默或刻意简短的语气。
  旧配置的 `style_variation_probability` 非零值仍生效，建议升级后调整为 `0`。
- `social_register_enabled` 默认开启：本地分析近期真人句长、当前闲聊意图和机器人
  最近的真实发言，动态提醒模型跟随短句节奏、接住吐槽或玩笑，并避开已经重复使用的
  开头、收尾和跨消息口癖；连续用问句收尾时也会提醒不要逢话必问。对方说“去忙了”
  “回头聊”等明确收尾时，只自然收住，不追问或另起话题。Planner 同时会更倾向不插话。
  这些分析不增加模型调用，也不学习或保存额外文本。
- `output_cleanup_enabled` 默认开启：在 LLM 响应阶段保守清理未要求的动作、神态、
  内心旁白和常见客服式结尾，减少“（笑了笑）”“*歪头看你*”这类角色扮演痕迹。
  普通“（笑）”不会被误删；代码、JSON/教程等结构化任务以及用户明确要求的角色扮演
  会完整保留。清理只作用于文本，不改动工具调用和其他消息组件。

这两项解决的是语域与表达习惯，不会把机器人伪装成生物学意义上的人类。真正的群聊
自然度仍依赖当前模型能力、稳定人格和足够的真实上下文，建议用 `/maieval` 做多消息测试。

## 启用顺序

插件默认只启用自然表达层。Planner 和所有自动学习能力默认关闭，避免在未确认成本、
隐私和群聊范围前产生额外模型调用。

推荐按下面顺序启用：

1. 配置 AstrBot 的稳定人格并观察基础表达效果。
2. 设置 `learner_provider_id`，启用表达学习和黑话学习。
3. 使用 `/mailearn` 在当前聊天手动执行一次学习，检查结果数量。
4. 为 Planner 设置便宜且 JSON 遵循能力好的模型。
5. 设置自主发言白名单，再开启群聊自主发言。
6. 确认 AstrBot 核心 `provider_ltm_settings.active_reply.enable` 已关闭。
7. 开启行为反馈学习，先观察 `/maiknowledge` 中的经验是否符合预期。
8. 多群运行时再启用 Focus，并设置 Focus 白名单和保持时间。
9. 开启中期聊天回想，并通过 `/mailearn` 和 `/maiknowledge` 检查摘要质量。
10. 有已学表达后可开启 `expression_selection_enabled`，测试语义筛选是否优于本地匹配。
11. 最后根据实际需要决定是否启用人物事实和私聊学习。
12. 使用 `/maieval` 对自己的真实聊天消息做多次对比，再决定使用哪些增强能力。

如果 AstrBot 核心主动回复与插件 Planner 同时开启，插件会暂停自己的自主回复并记录
警告，避免重复发送。

## 命令

```text
/maihumanizer
```

显示当前聊天的 Planner、Focus 和反馈观察状态，以及表达、人物、行为与聊天回想等
记录数量。

```text
/mailearn
```

管理员命令。立即使用当前聊天缓冲区运行一次学习；至少需要 4 条可学习消息。

```text
/maiknowledge
```

管理员命令。预览当前聊天学到的表达、黑话、行为经验、聊天回想和当前用户事实，
每类最多显示 5 条。

```text
/maiforget scope
/maiforget user
```

管理员命令。前者清除当前聊天的表达、黑话、行为经验、聊天回想和临时观察缓冲区，
后者清除当前说话者的人物事实。学习任务运行期间会拒绝清除，避免后台任务把数据
立即写回。人物事实按平台用户跨聊天保存，因此 `/maiforget user` 会等待所有聊天的
学习任务完成后再允许清除。

```text
/maifocus
/maifocus release
```

管理员命令。查看当前 Focus 占用情况，或手动释放关注槽。

```text
/maieval 测试消息
```

管理员命令。对比原版与增强版的实际模型输出，返回原文与匿名评审结果。支持包含空格的
完整测试消息；不带参数显示调用次数与使用说明。

## 成本与隐私

- Planner 每达到一次判断间隔会产生一次额外模型调用。
- 自动学习每累计一个批次产生一次额外模型调用。
- 中期回想复用自动学习批次，不会为同一批消息再单独调用一次模型。
- 行为反馈在一次自主发言收集到足够后续消息后产生一次额外模型调用。
- 群聊白名单、判断间隔、冷却和批次大小是主要成本控制项。
- 私聊默认不观察、不进入学习缓冲区。
- 人物事实只允许稳定、低敏感度的明确自述；敏感字段在学习提示中明确禁止。
- 群聊人物事实注入默认关闭，开启后也只注入当前聊天来源的事实。
- 人物事实的来源必须属于该说话者，黑话必须实际出现在引用的来源文本中。
- 旧版没有聊天来源的人物事实保留在存储中，但不再自动注入；需要在当前聊天重新学习，
  或用 `/maiforget user` 清除。
- 模型输出中的空来源、类型错误和非有限数值（如 NaN）会被丢弃或降为无置信度。
- 多个后台学习任务的持久化写入会串行执行，避免慢写入覆盖较新的学习结果。
- 学习结果保存在 AstrBot 插件隔离 KV 存储中。
- 聊天回想只保存压缩后的标题、摘要和召回线索，不保存来源消息正文。
- 管理员可以随时使用 `/maiknowledge` 审阅，并用 `/maiforget` 删除当前范围的数据。

启用人物学习前，应根据实际部署地区和使用场景完成必要的隐私告知、同意与数据保留
策略。

## 与完整 MaiBot 的差距

当前版本已经形成“观察 → 决策 → 回复 → 学习 → 召回”的核心闭环，但还不包含：

- MaiBot Focus 中由模型主动读取其他聊天和执行 `switch_chat` 的工具能力；
- 行为经验的场景聚类、共享组和复杂维护任务；
- 向量化表达、行为和回想检索；
- 跨聊天长期记忆图谱、记忆纠错和完整人物心理画像；
- 语义表情包理解、选择和发送；
- MaiBot 的完整插件运行时和 WebUI 管理页面。

这些能力适合在后续版本逐项适配，不应该直接把 MaiBot 的内部架构整体嵌入 AstrBot。

## 验证

本次已在 AstrBot 4.29.1 上通过 87 项测试，Ruff 检查与格式检查通过；此前版本已在
AstrBot 4.24.0 上完成兼容性验证。

本插件没有新增运行时第三方依赖。在插件目录中安装开发依赖并运行：

```bash
uv venv --python 3.12
uv pip install -r requirements-dev.txt
uv run --no-project pytest -q
uv run --no-project ruff check .
uv run --no-project ruff format --check .
```

测试使用真实 AstrBot 的 `ProviderRequest` 和会话序列化，验证增强参考可发送但不进入
持久历史，同时覆盖无关表达过滤、筛选降级、并发决策与过期丢弃、学习证据归属、
跨聊天事实隔离，以及 A/B 请求一致性与随机标签映射。模型调用在自动测试中模拟，
这些测试证明请求链路和回归行为，**不代表已经测得真实模型输出提升**。

另外覆盖真实 `At`/`Reply` 对象、较旧引用支线优先召回、缺失引用降级、私聊临时衔接、
可见发言过滤、决策连续性与发送状态。新增覆盖短句语域提示、重复开头与跨消息口癖、
连续问句、明确收尾、低信息量焦点选择及最新请求优先、旁白与机械收尾清理、正式任务/
角色扮演保护、连续自主发言后的真实静默。当前环境没有可用模型凭据，未执行真实模型 A/B。

建议部署后至少比较以下消息，每类选择多个实际案例：

| 场景 | 示例 | 重点检查 |
| --- | --- | --- |
| 情绪分享 | 今天忙了一整天，真的不想动了 | 接住感受，不机械列建议 |
| 分享成果 | 终于交稿啦 | 肯定具体内容，不生硬套梗 |
| 严肃求助 | 我最近状态很差，想找个人说说 | 不抽取玩笑语气 |
| 格式任务 | 只返回 JSON，列出三个城市 | 输出仍能被 JSON 解析 |
| 复杂问题 | 详细解释事务隔离，并给出例子 | 信息和步骤不因拟人化被省略 |
| 无关历史 | 群里刚聊游戏，现在问发布计划 | 不硬套游戏表达或旧回想 |
| 引用支线 | 引用较早的发布消息：修好了，明天上线 | 围绕引用回应，不接到旁人的游戏话题 |
| 情境变化 | 先前很难过，现在说：处理好了，终于能休息 | 跟上当前变化，不停留在旧情绪里 |
| 不愿继续 | 机器人刚问发生了什么，用户说：先不聊这个 | 不重复追问，不自行补全原因 |
| 去角色扮演 | 普通闲聊中模型原拟输出“（笑了笑）你说得对” | 只发送自然台词，不发送动作旁白 |
| 保留扮演 | 用户明确要求角色扮演和动作描写 | 不按日常群聊规则清理剧情文本 |
| 参与节奏 | 机器人已连续自主接话两次，群里仍有多人聊天 | 至少静默一次，精准提及仍能正常回应 |
| 连发焦点 | 先问“部署后旧版本怎么排查”，随后有人只发“哈哈” | 不错过实质问题，也不因焦点建议而强行插话 |
| 最新优先 | 旧话题讨论游戏，最新消息直接 @ 机器人问部署 | 不让旧焦点覆盖新的明确请求 |
| 自然收尾 | 用户说“我先去忙了，回头聊” | 不追问、不抛新话题；未直接被叫到时倾向安静 |
| 抑制口癖 | 机器人连续多条使用同一句式并以问句收尾 | 换新反应，不机械复读或继续习惯性反问 |
